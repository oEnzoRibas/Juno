# Governance

Enzo Ribas is Juno's founder and original creator. Juno is an independent, community-driven project for the Junior Enterprise movement. Project maintainers and administrators of a deployed instance have separate responsibilities.

## Open-source commitments

The official project keeps core features freely accessible, including management, recognition, and learning, and supports independent deployments. Maintainers favor reproducible setup, low infrastructure requirements, accessible workflows, and portable integrations. These commitments guide the official project. The [MIT License](LICENSE) defines rights and conditions for forks and derivatives.

## Decisions and responsibilities

The project owner has approved MIT for the software and associated project documentation and approves the first public release. Maintainers triage contributions, record decisions publicly where appropriate, review security and privacy, keep contribution paths accessible, and accept changes after validation. Seek independent review for security-sensitive changes when available. Handle review conflicts through an uninvolved maintainer where possible.

Contributors can propose changes through issues, discussions, and pull requests when available. Record product decisions in specifications and technical decisions in ADRs. Preserve contributor credit and license notices. See [contributing](CONTRIBUTING.md), [community strategy](docs/governance/community.md), and the [release process](docs/governance/release.md).
