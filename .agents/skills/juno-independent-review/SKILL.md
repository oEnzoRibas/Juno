name: juno-independent-review
description: Independently qualify a pinned Juno candidate and report reproducible platform and regression evidence. Use for independent QA, release readiness evidence, or integration handoffs.
---

Confirm the assigned scope, exact head, base or included parents, and reviewer independence. Keep your validation separate from the implementation worktree and report any overlap in authorship. Read the [maintainer review standard](../../../docs/development/git-workflow.md#maintainer-review-standard) and applicable [quality gates](../../../docs/testing/README.md). Use [juno-review-environment](../juno-review-environment/SKILL.md) if building or recovering an isolated runtime.

1. Compare the reviewed diff and actual runner with the expected coverage. Run the candidate's standard validator or the repository review launcher where applicable. For schema 8 verify that the runner executes each SQL in the [schema 8 contract](../../../scripts/quality/schema8-regression-contract.mjs) once. Separate runtime/API assertions from UI presentation checks. Exercise affected negative tenant and role cases using synthetic data. For concurrent profile writes, confirm the persisted audit assertion when in scope.
2. Read the command exit, named SQL assertions, structured browser summary, actual hosted jobs and cleanup results. A successful standalone run covers its own head and runtime. Name any missing sibling prerequisite and record a separately pinned composition when needed. Use the existing [recovery](../../../docs/testing/juno-database-recovery.md) or [production installation qualification](../../../docs/testing/juno-production-installation.md) only for relevant recovery work.
3. Report exact SHA and tree, source inputs and bases, commands, runtime/provenance, scope and result counts, failures and skipped checks, limitations, and the next owner action. Distinguish independent local evidence, implementation-owner results, hosted results, and human acceptance. Describe re-runs with changed setup as separate observations. Omit credentials, session values, private fixture files and sensitive response bodies. Publish in the authorized review channel.
