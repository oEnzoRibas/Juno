# ADR-0015 — Dependency-aware execution within Juno's ownership lanes

- **Status** Proposed for controlled trials on 2026-11-26.
- **Decision owner** Juno maintainer. [JUNO-0055 authorization](https://github.com/oEnzoRibas/Juno/issues/128) covers experiments and review publication. Adoption awaits a recorded maintainer decision.
- **Parent decisions** [ADR-0011](0011-three-agent-development.md), [ADR-0013](0013-review-build-provenance.md) and proposed [ADR-0014](0014-agent-harness.md).

## Problem

A passing validator on PR #40 left a required SQL file unexecuted. Its reviewer opened a separately pinned browser preview, and the maintainer's first run had no recorded overall exit code. More agents reading the same green summary would reproduce the inference error. A later review separated the fixture multiset, runtime identities and ownership of the observations. Those incidents motivate deterministic checks, independent reproduction and separate acceptance gates. They provide no timing comparison across topologies. [Original correction](../../development/history/JUNO-0042-pr-40-runtime-review.md) and [stack #42 qualification](../../development/history/JUNO-0044-stack42-review.md).

## Decision for the experiment

Retain Agent 01 for core and coordination, Agent 02 for frontend and design, Agent 03 for platform and independent quality, and Agent Researcher for scientific records. The registry owns claims. A deterministic graph projects eligible work from contracts. Agent 01 commits the dispatch decision after checking the current registry, exact revisions, admissible resources and active reservations. It may run a single task in one lane, a serial pipeline, or parallel independent branches with a verified join. A temporary specialist receives one finite question, an input pin and a stop condition. An already-authorized host agent can carry this contract if a project profile is unavailable. See the [operating manual](../../development/harness/v2/operations.md).

The selected trial adds graph validation to the hybrid organization. For a single-document correction the coordinator can keep a single owner and one final check. For a full-stack change, publish the API contract first, release separate frontend and backend scopes, join their pinned artifacts, then assign a fresh integrated review. This preserves cheap serial work and makes the expensive split testable.

## Consequences and reversal

Overhead includes writing a contract, waiting for dependencies and checking results from several sessions. Graph validation cannot establish actual runtime behavior, authorization or reviewer independence. A corrupted packet or stale base can invalidate a whole join. Keep raw failed attempts and revalidate before reassignment. If accepted outcomes per elapsed hour fail to improve or correctness falls, return affected work to one owner with the existing gates. Retain complete experimental records. Repeat with matched inputs before broad adoption. [Migration and decision gates](../../development/harness/v2/migration.md).
