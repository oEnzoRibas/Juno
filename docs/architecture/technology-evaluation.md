# Technology evaluation

**Status:** Desktop evaluation for Phase 1. Implementation choices below remain subject to approval, version and license review, and applicable prototype evidence. Favor maintained dependencies with approachable documentation and a self-hosting path.

| Area                   | Candidates and trade-offs                                                                                                                                                                                                                                                                                      | Evidence or decision trigger                                                                                                                                                                                                                                                                    |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Language and web       | TypeScript with React supports a shared contributor ecosystem. Compare Next.js with a React single-page shell or progressively enhanced server pages. Next.js provides application routing and server features, with added framework/runtime choices.                                                          | Compare accessibility, localization, session boundaries, host requirements, testing, and maintenance. [Next.js backend guide](https://nextjs.org/docs/app/guides/backend-for-frontend)                                                                                                          |
| Modular API            | NestJS provides explicit modules. Compare it with framework routes and a thin HTTP server plus application modules. NestJS adds conventions and a separate backend to operate.                                                                                                                                 | Implement the same small authorized workflow during a future approved spike. [NestJS modules](https://docs.nestjs.com/modules)                                                                                                                                                                  |
| Storage                | PostgreSQL is a strong candidate for relational constraints, transactions, durable jobs and row policies. Compare isolated schemas or databases and evaluate operator overhead.                                                                                                                                | Validate non-bypassing roles, pooled context, migrations, restore and tenant export. [PostgreSQL row policies](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)                                                                                                                    |
| ORM and migrations     | Prisma offers a schema and generated client. Drizzle exposes a SQL-oriented model. Compare a driver and reviewed SQL where direct policy DDL is a better fit.                                                                                                                                                  | Prove roles, RLS, composite tenant constraints, transaction-bound context, repeatable migrations and recovery with each shortlisted option. [Prisma migrations](https://www.prisma.io/docs/orm/migrations/the-migration-graph) · [Drizzle migrations](https://orm.drizzle.team/docs/migrations) |
| Contracts              | Compare REST with OpenAPI against server-only calls for a combined application. Compare schema-first tools with Zod-based runtime validation and framework metadata. Swagger UI is a candidate for rendering OpenAPI.                                                                                          | Pick one contract source and detect drift. Verify errors, auth, locale and retry behavior. Treat client validation as feedback. [OpenAPI specification](https://spec.openapis.org/oas/latest.html) · [Zod](https://zod.dev/) · [Swagger UI](https://swagger.io/tools/swagger-ui/)               |
| Styling and components | Tailwind CSS and shadcn/ui can accelerate a React prototype. Compare component CSS and selected accessible primitives. Copied components need code, update and accessibility ownership.                                                                                                                        | Test keyboard, contrast, themes, responsive behavior and semantic tokens. [Tailwind CSS](https://tailwindcss.com/docs) · [shadcn/ui](https://ui.shadcn.com/docs)                                                                                                                                |
| Localization           | Evaluate next-intl with Next.js. Compare framework-neutral message catalogs and locale formatting if web delivery changes.                                                                                                                                                                                     | Verify typed message keys, fallback, dates, pluralization and long pt-BR strings. [next-intl](https://next-intl.dev/)                                                                                                                                                                           |
| Documentation          | Prefer version-controlled Markdown. Evaluate TSDoc and TypeDoc if TypeScript is selected. Compare GitHub Markdown with Docusaurus for navigation, search, versioning, hosting and upkeep. Compare Mermaid and C4 scope with text and other diagram generation tools when layout or model reuse warrants it.    | Validate links, public API references and accessible text equivalents. [TypeDoc](https://typedoc.org/) · [Docusaurus](https://docusaurus.io/docs) · [Mermaid](https://mermaid.js.org/intro/) · [C4](https://c4model.com/)                                                                       |
| Workspace and delivery | pnpm Workspaces can link real consumers. Compare npm workspaces or one package. Evaluate Turborepo only if measured build complexity warrants orchestration. Docker and Docker Compose are required under [ADR-0005](adr/0005-mandatory-containerization.md). Evaluate image design and the reference rollout. | Reproduce setup, build, upgrade and restore on a clean host. [pnpm](https://pnpm.io/workspaces) · [Turborepo](https://turborepo.com/docs) · [Docker Compose](https://docs.docker.com/compose/)                                                                                                  |
| Automation and testing | Evaluate GitHub Actions for CI, Vitest for TypeScript unit tests, Playwright for browser flows, and Testcontainers for real dependencies. Compare built-in test runners and dedicated CI services.                                                                                                             | Measure deterministic two-tenant checks, browser coverage and CI startup cost. [GitHub Actions](https://docs.github.com/en/actions) · [Vitest](https://vitest.dev/) · [Playwright](https://playwright.dev/docs/intro) · [Testcontainers](https://testcontainers.com/)                           |
| Observability          | Begin from structured logs and health endpoints. Evaluate OpenTelemetry when traces across API, jobs, and providers justify it.                                                                                                                                                                                | Check correlation and redaction. Exclude sensitive values from telemetry. [OpenTelemetry](https://opentelemetry.io/docs/what-is-opentelemetry/)                                                                                                                                                 |
| Assets and jobs        | Compare local storage with S3-compatible storage behind an adapter. Evaluate PostgreSQL-backed persistent jobs against a synchronous transaction for short work. Consider Redis or Valkey only after measuring an unmet cache or job requirement.                                                              | Verify scoped paths, signed retrieval, restore, portable storage, retry and crash recovery. [Amazon S3 API](https://docs.aws.amazon.com/AmazonS3/latest/API/Welcome.html) · [PostgreSQL locking](https://www.postgresql.org/docs/current/explicit-locking.html)                                 |

Compare self-hostable OIDC, framework-managed identity and managed OIDC on revocation, MFA, recovery, operating effort and portability. Record provider choice separately from authorization policy.

Before installation, verify authoritative supported-runtime and integration requirements, maintenance, release provenance and vulnerabilities. Record exact selected versions, direct and transitive license review, notice obligations, and compatibility with MIT distribution. Record estimated resource and cost figures after measuring the approved prototype. No application dependencies are installed by this evaluation.
