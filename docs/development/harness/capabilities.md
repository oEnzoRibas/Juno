## Verified versus documented behavior

Codex discovers local project skills while walking from the current directory to the repository root. The [Agent Skills specification](https://agentskills.io/specification) defines the name, description and optional resources. The [official skill guide](https://learn.chatgpt.com/docs/build-skills) covers implicit matching, explicit invocation, Skill Creator and Skill Installer. Record discovery and actual use as different observations. Use the bundled creator and its validation for local files. Review repository, release or commit, license, dependencies and execution paths before any optional installation.

The [Codex configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) describes trusted project config and supported agent fields. The [agent workflow guide](https://learn.chatgpt.com/docs/multi-agent) describes delegation. Use the CLI or app-server schema observed on the workstation for compatibility. Parent scopes apply to subagents. The host enforces actual permissions. A fresh task with an exact handoff is the recovery path when contextual history is compacted or interrupted.

## Permission strategy

- Routine read-only review uses the host's read-only profile when available. Approved implementation uses an isolated writable worktree and only its reserved paths. See [permissions](https://learn.chatgpt.com/docs/permissions) and [sandbox and approvals](https://learn.chatgpt.com/docs/agent-approvals-security).
- Use dedicated authenticated publication paths for approved GitHub branches, issues and PRs. Production credentials, unrestricted filesystem access, live databases, approval defaults, machine paths and private server configuration stay out of project config.
- The maintainer controls merges, production access, destructive actions, externally published assets or messages beyond the authorized review work, credential disclosures and newly billed services.
- Review a third-party tool or skill's publisher, version or exact source revision, license, dependencies, requested access and output destination. Record approval and effective available operations. A documentation example does not grant authorization. See the [official MCP overview](https://learn.chatgpt.com/docs/extend/mcp) and [Computer Use](https://learn.chatgpt.com/docs/computer-use).

## Photoshop decision and local proof

[Adobe's scripting guide](https://helpx.adobe.com/photoshop/desktop/automate-tasks/automation-settings-and-presets/automate-photoshop-with-scripts.html) documents desktop automation. The [legacy Windows scripting guide](https://helpx.adobe.com/ph_fil/photoshop/using/scripting.html) describes COM. The [UXP documentation](https://developer.adobe.com/photoshop/uxp/ps_reference/media/uxpscripting/) and [Photoshop DOM](https://developer.adobe.com/photoshop/uxp/ps_reference) describe modern in-app scripts. Prefer DOM operations and use [batchPlay](https://developer.adobe.com/photoshop/uxp/ps_reference/media/batchplay/) for gaps that can be validated.

Qualify application version, session access, native PSD create, a meaningful edit to named groups or layers, save, reopen and inspection of persisted structure. Check non-destructive editability and a transparent preview independently. GUI use is optional where it can add an authorized rendered inspection. A created file or COM registration alone is insufficient.

Start with an explicit local script or a narrow CLI bridge under the creative workspace. Consider an MCP adapter after repeatable proof and independent validation. A candidate adapter should offer allowlisted document operations, validated input and destination paths, explicit overwrite semantics, deterministic errors and inspectable outputs. Unrestricted script execution, persistent listeners, purchases and production dependencies are outside this increment.
