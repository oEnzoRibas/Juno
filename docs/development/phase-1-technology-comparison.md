# Phase 1 technology comparison

**Status:** Desktop assessment. No versions are pinned and no packages were installed. The shortlist below requires owner review and a container-based compatibility spike under [JUNO-0018](tasks/JUNO-0018.md).

| Scope | Candidates and trade-offs | Evidence to approve |
| --- | --- | --- |
| UI and HTTP | Next.js with React plus NestJS offers an explicit API and backend module conventions. A single Next.js app reduces deployment and same-origin session overhead. A small typed REST server is another candidate if Nest conventions add excessive overhead. | Same invite and tenant read workflow across the shortlisted topology. Measure startup, development reload, review burden, origin and session policy, and operating footprint. |
| Relational storage | PostgreSQL provides tenant keys, row policies and transactions. Compare shared schema plus RLS with schema or database per tenant. Compare Prisma's generated client and migrations with Drizzle's SQL-oriented workflow and plain reviewed SQL. | Prove role policy DDL, composite keys, restricted roles, pooling safety, fixtures and recovery. Verify runtime libraries and Linux image variants. |
| Workspaces and builds | pnpm Workspaces supports a single lockfile. Compare npm workspaces or a single package when the topology is integrated. Measure a root task runner before adding Turborepo orchestration or caching. | Clean lockfile install and repeatable build, script ergonomics, cache benefit, import restrictions. |
| UI system | Tailwind CSS and shadcn/ui primitives are candidates for quick consistent UI composition. Compare CSS Modules with reviewed accessible primitives. Copied components require ownership and dependency notice review. | Demonstrate branded theme tokens, en/pt-BR, keyboard focus, dark contrast, zoom and responsive behavior. |
| API and references | Prefer evaluating REST and OpenAPI for a genuine external web/API contract. Compare schema-first generation with Nest-generated schemas. Use TSDoc and TypeDoc if exported interfaces merit publishable references. | Verify schema and runtime validation agree. Document typed errors, authorization, backwards compatibility and generated-reference drift. |
| Tests | Vitest for typed unit tests, Playwright for browsers and Testcontainers for integration tests. Compare Node's test runner for simple units, and Compose-managed disposable database services where Docker socket access is constrained. | Verify deterministic test isolation, supported Node versions, browser dependencies, runner restrictions, and containerized execution. |

## Runtime intersection and portability

Official Next.js documentation lists Node 20.9 as its minimum. Nest distinguishes runtime requirements from its stricter generator requirements. Prisma ORM v7 lists Node 20.19, 22.12, or 24 lines with stated patch ranges, and TypeScript 5.4 or later for TypeScript users. Evaluate the supported Node 24 LTS line with a patch satisfying every chosen framework and generator. Pin only after verifying actual releases, pnpm packaging and host architectures, React/framework peer versions, Testcontainers runner access, and image system libraries. These are documented compatibility constraints, not tested integration results. [Next.js installation](https://nextjs.org/docs/app/getting-started/installation) · [Nest first steps](https://docs.nestjs.com/first-steps) · [Prisma v7 requirements](https://www.prisma.io/docs/orm/v7/reference/system-requirements) · [pnpm installation](https://pnpm.io/installation)

Before pinning, inventory direct and transitive licenses, copied component and font notices, image base and OS package licensing, dependency updates, and software bill of materials output. Benchmark CPU, memory, storage, operator time and current cost on an independent deployment. Reject any stack that forces the production host to rely on a third party or compromises tenant controls.
