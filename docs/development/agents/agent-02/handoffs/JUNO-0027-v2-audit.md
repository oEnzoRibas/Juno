# JUNO-0027 V2 design intervention and reviewed build audit

**Date:** 2026-11-25. **Review state:** Changes requested. Interaction acceptance remains pending. The new direction requires a fresh design approval.

[PR #37](https://github.com/oEnzoRibas/Juno/pull/37) previously published shell head 3101ac7a26e2b621d32c996138f8dc33f7d52cae. The actual reviewed preview used commit 4f6ab8f56bc94cecf9ece5651e1d42d7cd63c0c7 with implementation 5f8ecfc1ffeffe68043163229f8f317c7cdc3028. Chromium verified the build indicator before measuring, using Atlas administrator and PT-BR. The written attachment had no image files in its upload directory. This record uses archived captures and new screenshots of the verified preview. Its running configuration and database were preserved.

| Finding | Reproduction and evidence | Result and source |
| --- | --- | --- |
| Account popup outside viewport | At 320/375/390 × 900 CSS px, open the person icon in the header. Read the open panel bounding rectangle. [320 screenshot](../evidence/v2-audit/account-320.png) · [390 screenshot](../evidence/v2-audit/account-390.png) | The left edges were −57, −52 and −44 px. Document width equals viewport width, so page width alone misses clipping. The panel is absolutely aligned to the small summary, with width independent of available space to its left. See application-shell.module.css, .accountMenu and .accountControls. |
| Mobile navigation and accessibility controls | At 320 × 900, compare the desktop account control with the mobile account and language placement. Open the navigation drawer and inspect the 320 px archived frame. [Drawer](../evidence/shell-review/juno-shell-after-mobile.png) | Header measured 140 px at 320–390 versus 68 px at 768–1920. Locale appears as an alternate-language link, theme is behind the account icon, and sign-out is beside it as a separate visible action. The drawer shows a close icon and separated navigation. Keyboard Escape closed the account disclosure and focus remained on its summary in the tested case. See ApplicationShell and ShellPreferences. |
| Alignment, sizing and available space | Compare 320 and 1280 × 900 and inspect platform provisioning. [Desktop account](../evidence/v2-audit/account-1280.png) · [Platform](../evidence/shell-review/juno-shell-after-platform.png) | Wide form panel carries a much narrower input column. The header mixes underlined text and equal-height icon controls that read as different groups. At mobile the wrap separates related controls across header rows. See .headerActions, .sectionPanel and ProvisionForm. |
| Hierarchy, whitespace and actions | On the 1440 px archived dashboard compare the small membership panel with the taller invitation form, accents, breadcrumb, and underlined Cancel. [Dashboard](../evidence/shell-review/juno-shell-after-desktop.png) | Invitation controls compete with the workspace heading and role, while the wide region below remains largely empty. Native text links and filled buttons are qualitatively distinguishable but use inconsistent relative alignment and emphasis. See Workspace, .dashboardGrid and InviteForm. These are visual review observations. |
| Authentication form balance | Open public sign-in at 320 and 1280 × 900. Compare brand, heading, fields, action and language. [Mobile](../evidence/v2-audit/login-320.png) · [Desktop](../evidence/v2-audit/login-1280.png) | Desktop uses a centered wide panel, with field and action content occupying only its left region. Narrow layout stacks the heading and form but keeps the original panel hierarchy. V2 aligns all important fields and the action and brings locale into a consistently labeled position. See sign-in/page.tsx, .public-shell and .public-panel. |

[Raw viewport observations](../evidence/v2-audit/local.json) also cover 768, 1024, 1280 and 1920 px. Those viewports kept the account panel within the screen in this run. The inspection did not establish screen-reader output or independent accessibility conformance. No production or auth changes were made.
