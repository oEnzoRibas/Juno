# Ownership and interface contracts

| Owner | Default work                                                                                                                     | Contract published to the other owners                                                                                                     |
| ----- | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 00    | Backlog, claims, ADR coordination, integration, escalation                                                                       | Exact base, owner, reserved paths, acceptance criteria and integration candidate                                                           |
| 01    | `apps/api`, PostgreSQL schema and migrations, domain modules, REST and OpenAPI                                                   | HTTP schemas and compatibility, authentication and RBAC rules, tenant scope and isolation, migration requirements, versioned domain events |
| 02    | `apps/web`, approved design and brand assets, UI mockups, accessibility and localization, onboarding, navigation and dashboard   | Input/output of components, tokens, user journeys, accessibility acceptance, frontend build requirements                                   |
| 03    | Compose, Dockerfiles, deployment, GitHub Actions, validation harness, system-level quality, security, observability and recovery | Image and environment configuration, CI commands and evidence, security findings, recovery and deployment requirements                     |

Agent 00 coordinates shared repository files and assigns exact writable paths. Agent 01 owns backend contracts and database schemas. The Researcher owns the living orchestration views under explicit reservations and independently maintains the private Notebook. Agent 03 owns Compose changes after transfer. Agent 01 and Agent 03 jointly verify migration or container changes that cross the schema and startup boundary. Agent 02 and Agent 01 agree on API and frontend version compatibility. Ownership of a directory does not override any active path reservation.

Publish the current branch SHA, schema and compatibility status before transferring a changed contract. Obtain explicit agreement on implementation order across agents and record review or migration requirements. Preserve compatibility until the owner approves a planned breaking change. Independent security and QA findings go back to the owning agent, with reproduction and private security reporting where required.
